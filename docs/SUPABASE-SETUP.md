# إعداد Supabase لميزة «ملاحظاتي»

دليل خطوة بخطوة: ما يُنفَّذ في لوحة Supabase، وما يُنفَّذ في المستودع، وما الذي
يُتحقَّق منه بعد. **لا يُرفع أي سرّ إلى المستودع أبدًا** — ملفات الإعداد
الحساسة محلية (`.env.local` مُستثناة من Git) أو أسرار المستودع (Repository
Secrets)، والملف `supabase.info.txt` مُستثناة من Git أيضًا.

---

## 1) لصق SQL الجدول والحماية (الطلب الأساسي)

1. Supabase Dashboard ← **SQL Editor** ← **New query**.
2. افتح الملف `docs/supabase-notes.sql`، انسخ **كله**، الصقه، اضغط **Run**.
3. النجاح المتوقع: `Success. No rows returned.`
4. تحقّق داخل المحرّر:

```sql
select count(*) from public.notes;  -- يجب أن ترجع 0
```

ماذا يفعل SQL: جدول `notes` بقيود طول، وفهرس «الأحدث أولًا لكل مستخدم»،
ومشغّل يضبط `updated_at` من قاعدة البيانات، و**تفعيل RLS**، وأربع سياسات ملكية
(`auth.uid() = user_id`)، وسحب كل الصلاحيات عن دور `anon`.

## 2) روابط الدخول — شرط لأول رابط سحري

Dashboard ← **Authentication** ← **URL Configuration**:

- **Site URL**: `https://hnyth50-gif.github.io/dhikri/`
- **Redirect URLs** ← Add:
  - `https://hnyth50-gif.github.io/dhikri/*`
  - `http://localhost:4173/*` (للمعاينة المحلية — اختياري)

بدون هذه الخطوة يرفض Supabase رابط العودة بخطأ `Invalid Redirect URL` —
والواجهة تعرض رسالة عربية صريحة بذلك.

## 3) إبطال المفتاح السري المكشوف (إجراء أمني إلزامي)

المفتاح `sb_secret_…` الموجود في `supabase.info.txt` ظهر في ملف نصي على القرص
— يُعامل كمكشوف. من **Settings ← API ← Rotate secret keys** أبطله وألغي القديم.
الموقع لا يستعمل المفتاح السري في أي مكان (فحص e2e يتأكد من غياب `sb_secret`
في الكود المنشور)؛ المتصفح يستعمل المفتاح القابل للنشر `sb_publishable_…`
وحده — وهذا **مصمَّم ليكون ظاهرًا** في أي مستودع مفتوح؛ الأمان كله في RLS.

## 4) أسرار المستودع (متغيّرات البناء)

Settings ← **Secrets and variables** ← **Actions** ← **New repository secret**،
باسمي القيم نفسها المسجلة في `.github/workflows/deploy.yml`:

| الاسم | القيمة |
| --- | --- |
| `VITE_SUPABASE_URL` | `https://enpwfckyzwhenymxgyrb.supabase.co` |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_…` (من supabase.info.txt) |

بلاها: يُبنى الموقع كاملًا وتعمل كل الوظائف، **والميزة وحدها تعرض حالة صادقة
«غير مفعّلة»** — لا ادّعاء ولا انهيار.

## 5) الرسائل البريدية

Supabase يرسل روابط الدخول عبر خدمته المدمجة بحدود مجانية (بضع رسائل في
الساعة على الخطة المجانية). عند التوسع: **Auth ← Emails ← Custom SMTP**.

## 6) تحقّق نهائي بعد النشر

1. افتح `#/notes` → اكتب بريدك → «أرسل رابط الدخول» → يصلك رابط → افتحه →
   تظهر قائمة ملاحظات فارغة مع عنوان بريدك و«خروج».
2. أضف ملاحظة → أعد التحميل → تبقى (تُجلب من القاعدة).
3. من جهاز/متصفح آخر: ادخل بنفس البريد → ترى الملاحظات نفسها.
4. من تبويب خاص بلا دخول: استعلام القاعدة يرجع فارغًا (RLS) — ولا زائر يرى
   شيئًا مهما كان.

## حدود صريحة

- **SQL يُنفَّذه صاحب الموقع من لوحته** (هذه البيئة بلا صلاحية لوحة تحكم) —
  نصه مراجَع ومحسوب على واجهة Supabase الحالية.
- اختبار الدخول الفعلي بحساب حقيقي يحتاج بريدًا حقيقيًا — يُنفَّذ في خطوة 6
  أعلاه، ونتيجته تُوثَّق في `docs/TEST-REPORT.md`.
- رسائل البريد والحساب مسؤولية خدمة Supabase ومحدودة بخطتها المجانية.
