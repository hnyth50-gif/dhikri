# ذِكري (Dhikri)

**لحظات ذكر، وسكينة تتجدد.**

موقع عربي بالكامل (RTL) لأذكار الصباح والمساء، بنصوصٍ من القرآن الكريم والحديث الصحيح
ومصادرها مرفقة، مع عدّاد تسبيح تفاعلي لكل ذكر، وتقدّم يُحفظ محليًا، وعمل دون اتصال،
وصوتٍ واضحة للقارئ الشاشي.

لا خادم، لا قاعدة بيانات، لا مفاتيح سرّية، لا حسابات مستخدمين. كل شيء يجري داخل
متصفحك ويُحفظ في `localStorage`.

## التشغيل المحلي

```powershell
# في Windows (أو استخدم npm بلا .cmd في بقية الأنظمة)
npm.cmd install        # تثبيت الاعتماديات مرة واحدة
npm.cmd run dev        # خادم التطوير على http://localhost:5173
```

أوامر أخرى:

```powershell
npm.cmd run build      # فحص الأنواع ثم بناء مجلد dist/
npm.cmd run preview    # معاينة الإصدار المبني على http://localhost:4173
npm.cmd run typecheck  # فحص TypeScript بلا بناء
npm.cmd test           # البيانات + البناء + الاختبار الشامل (90 فحصًا)
```

> **ملاحظة Windows:** سياسة التنفيذ في PowerShell قد تحجب `npm`. استخدم `npm.cmd`،
> أو نفّذ أدوات vite/tsc مباشرةً:

## البناء والنشر

```powershell
npm.cmd run build      # ينتج مجلد dist/ جاهزًا للنشر
```

الموقع ثابت بالكامل: ارفع مجلد `dist/` إلى أي مضيف ملفات ثابتة
(GitHub Pages، Netlify، Cloudflare Pages، Firebase Hosting، خادمك الخاص…).

نقاط مهمة:

1. **لا إعداد خادم مطلوب.** التوجيه عبر `HashRouter` (`#/morning`)، فلا حاجة إلى قاعدة
   `rewrite` لـ `index.html`، ويعمل كل شيء من مجلد فرعي مثل `https://example.com/dhikri/`.
2. **المسارات نسبية** في `index.html` وفي تسجيل عامل الخدمة (`./sw.js`) — ولذلك يعمل
   الموقع من أي مجلد فرعي دون تعديل. (مُتحقَّق منه في `test:e2e`.)
3. **عامل الخدمة يتطلب HTTPS** (أو `localhost`). على استضافة عادية يعمل دون أي إعداد؛
   أما أثناء التطوير على `http://` غير localhost فيتجاهله المتصفح بصمت والموقع يعمل
   كموقع عادي تمامًا.
4. **حدّث `manifest.webmanifest` و`robots.txt`** إن نشرت على نطاق مختلف.

### النشر على GitHub Pages (الطريق الموصى به)

المشروع يحوي مسار عملًا جاهزًا: [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)
يبني الموقع وينشره تلقائيًا عند كل دفعة إلى `main`.

**الإعداد مرة واحدة فقط:**

1. ارفع المستودع إلى GitHub (انظر «رفع المشروع إلى GitHub» أدناه).
2. افتح المستودع على GitHub ← تبويب **Settings** ← **Pages**.
3. تحت **Build and deployment** اختر **Source: GitHub Actions** (لا تختار «Deploy from a branch»).
4. اذهب إلى تبويب **Actions** وسترى عملية `Deploy to GitHub Pages` تعمل؛ بعد نجاحها
   يظهر رابط الموقع أسفل الـ job وفي بيئة **github-pages**.

**من الآن فصاعدًا:** كل `git push` إلى `main` = تحديث فوري للموقع (يبني، يفحص البيانات، ثم ينشر).

مثال للرفع الأول:

```powershell
git init
git add .
git commit -m "ذِكري: أذكار الصباح والمساء"
git branch -M main
git remote add origin https://github.com/<user>/dhikri.git
git push -u origin main
```

### النشر على مضيف ثابت آخر

ارفع محتويات مجلد `dist/` كما هي إلى المضيف:

| المضيف | ما يُكتب في إعدادات النشر |
| --- | --- |
| Netlify / Cloudflare Pages | أمر البناء: `npm run build` · مجلد المخرجات: `dist` |
| Firebase Hosting | `firebase deploy` بعد ضبط `"public": "dist"` في `firebase.json` |
| خادمك الخاص | انسخ `dist/` إلى مجلد الويب (أي مجلد فرعي يصلح) |

لا حاجة إلى أي قاعدة rewrites لأن التوجيه بـ `HashRouter`.

## الميزات المنفَّذة

**المحتوى**

- 24 ذكرًا (23 صباحًا / 21 مساءً — منها ما هو مشترك)، نصوص كاملة بلا اختصار.
- كل ذكر يعرض مصدره ومرجعه ودرجة الحديث بحسب المصدر، وعدد التكرار **كما ورد في المصدر**
  منفصلًا عن هدفك الخاص (اختياري).
- **لا يُقدَّم أي نص على أنه صحيح دون مصدر**؛ ما لم يُتحقَّق منه يوضع في طابور مراجعة
  بارز في واجهة الموقع نفسه وفي صفحة «المصادر».
- بحث يتجاهل التشكيل والهمزات، ومفضلة، ومشاركة تشمل النص والمصدر معًا.

**التفاعل**

- عدّاد تسبيح حقيقي لكل ذكر: زر واحد يزيد، زر تصفير مع تأكيد، شريط تقدّم بـ
  `role="progressbar"`، ووصول كامل بلوحة المفاتيح (Tab + Enter/Space).
- هدف مخصّص لكل ذكر يُحفظ عبر الأيام، مع زر «إعادة لعدد المصدر».
- إنجاز الصباح والمساء منفصلان، وسلسلة أيام (streak)، وسجلّ يومي، وعدد التكرار مدى الحياة.

**التجربة**

- وضعان فاتح وليلي مع احترام تفضيل النظام وتطبيق قبل أول رسم (لا وميض أبيض).
- خمسة مستويات لحجم الخط تُطبَّق فورًا وتُحفظ، دون قص للنص العربي.
- أربعة خطوط عربية للاختيار من الإعدادات (افتراضيًا **Amiri**، ثم **Noto Naskh Arabic**،
  **IBM Plex Sans Arabic**، **Cairo**)، كلها مستضافة ذاتيًا.
- خيارات إضافية: السماح بتجاوز العدد المستهدف، واهتزاز خفيف عند الضغطة (معطّل
  افتراضيًا، ولا صوت تلقائي في أي موضع).
- إعادة تعيين لكل شيء من الإعدادات مع تأكيد صريح.

**الوصول والأداء**

- RTL كامل بخصائص CSS المنطقية (`margin-inline` بدل `left/right`)، وفحص آلي يمنع
  محاذاة `left/right` حرفيًا.
- رابط «تخطَّ إلى المحتوى»، تسميات عربية لكل زر أيقوني، `aria-current` للتنقل،
  عدّادات حيّة `aria-live`، وتباين لا يعتمد على اللون وحده.
- احترام `prefers-reduced-motion`، وتنسيق طباعة منفصل (`@media print`).
- **نتيجة Lighthouse على كل المسارات الستة:** إمكانية الوصول 100، أفضل الممارسات 100، SEO 100.

**دون اتصال**

- عامل خدمة مكتوب يدويًا: الصفحات شبكة أولًا مع رجوع تلقائي للنسخة المحفوظة،
  والثوابت نسخة أولًا مع تحديث في الخلفية، مع رجوع للنسخة المحفوظة عند أخطاء الخادم
  (502/503…) لا عند انقطاع الشبكة فقط.
- يُرسل لعامل الخدمة قائمة ملفات البناء بعد التحميل ليضعها في الذاكرة المؤقتة.
- **مُختبَر فعليًا:** إيقاف الخادم ثم إعادة تحميل الصفحة تُظهر الموقع كاملًا بلا أخطاء
  في الطرفية، والعدّاد يعمل ويحفظ.

## إدارة بيانات الأذكار

**الملف الوحيد:** `src/data/adhkar.ts`

كل ذكر يحمل على الأقل:

```ts
{
  id: "kursi",                 // معرّف فريد
  title: "آية الكرسي",         // العنوان المختصر
  kind: "quran" | "hadith" | "athar",
  time: "morning" | "evening" | "both",
  count: 1,                    // عدد التكرار كما ورد في المصدر
  countLabel: "مرّة واحدة",    // صياغة هذا العدد بالعربية (تُعرض بدل الرقم المجرّد)
  hisn: 75,                    // رقم الذكر في حصن المسلم
  text: "…",                   // نص الصباح كاملًا بلا اختصار
  eveningText: "…",            // صياغة المساء إن اختلفت
  virtue: "…",                 // فضله كما ورد في المصدر
  quranRef?: { … },            // لكل ذكر قرآني: السورة، الآية، رابط التلاوة
  sources: [ … ],              // مصادر مع رابط https ومندرجة تحته رقم مُتحقَّق منه أو لا
  verification: "verified-source" | "needs-review",
  verificationNote: "…",       // يُعرض في الواجهة عند وجود شك
  audio: { … }                 // تسجيل مسموع (روابط hisnmuslim)
}
```

**قواعد لا يتجاوزها `npm run test:data`:**

1. معرّفات وأرقام حصن فريدة، وعدد التكرار ‎> 0.
2. أي مرجع موسوم «مُتحقَّق» لابد أن يحمل رابط `https` صالحًا على sunnah.com.
3. أي مرجع غير مُتحقَّق لا يُعرَض على أنه مُتحقَّق (يظهر تنبيهه في الواجهة).
4. كل ذكر قرآني يحمل مرجعًا قرآنيًا كاملًا.
5. أقسام الصباح والمساء تغطي كل ذكر مخصص لهما تمامًا.
6. لا نقاط نهاية (`…`) ولا مسافات زائدة ولا اختصار — النصوص محرَّفة حرفًا حرفًا.
7. صيغة رابط التلاوة ثابتة ومشتقّة من رقم الذكر.

**لإضافة ذكر جديد:** أضِف الكائن إلى `DHKAR`، انتبه لصفته في القسمين صباحًا/مساءً،
ثم شغّل `npm run test:data`. سيفشل الفحص فورًا إن نقص مرجع أو كان الرقم غير مُتحقَّق منه
دون توثيقه.

**لتعديل صيغة عدد:** غيّر `count` (للمنطق) و`countLabel` (للعرض) معًا —
العدّاد يبدأ من صفر مهما كان المبلغ، وعدّاد المستخدم لا يُغيّر عدد المصدر.

## التخزين المحلي

كل البيانات في `localStorage` تحت مفتاحين فقط (راجع `src/lib/storage.ts` و`src/state/AppContext.tsx`):

| المفتاح | المحتوى |
| --- | --- |
| `dhikri:progress:v1` | عدّادات اليوم، إنجاز الصباح/المساء، المفضلة، سجلّ الأيام، عدد التكرار مدى الحياة، تاريخ اليوم الحالي |
| `dhikri:settings:v1` | الثيم، حجم الخط (1–5)، الخط المفضّل، التذكيرات (وقتها وتفضيلها) |

ومنفصلًا عن ذلك يطبَّق **الثيم وحجم الخط قبل أول رسم** من سطر صغير داخل `index.html`
(يقرأهما من `localStorage` مباشرة) فلا يظهر وميض أبيض عند فتح الموقع.

عند تبدّل اليوم: تُصفَّر عدّادات اليوم وتُنقل النتائج إلى `history`،
أما **الأهداف المخصّصة فتبقى كما هي**.

لا شيء يغادر جهازك. حذف بيانات الموقع يحذف كل شيء ويبدأ من جديد.
